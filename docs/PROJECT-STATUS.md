## M13 延期状态

`BetaValidationMetrics` 已把 16 项 Gate 指标和教师权利收口在一个深模块 Interface 中：严格枚举事件、HMAC 摘要 owner/task、按可信等级分层严重数学错误、零分母返回空值，并计算选择/导出/保存转化、留存、Tool 失败、成本与耗时。采集开关默认关闭；教师确认 `m13.notice.v1` 后才允许记录，事件保留 90 天，本人可以导出聚合或退出并删除本人事件。`BetaValidationFacts` 进一步隐藏采集状态、参与状态、事件映射和存储故障；Search/Solve、命题、Paper、Lesson、资料导入及私题保存已从服务端成功节点接入，主事件与完成/Tool 结果原子写入且任何指标故障不影响教师工作流。Search 只有点击真实结果才形成选择，搜索/解题评价要求 current-owner 的已完成 run 且最后一次决定生效。模型成本只接受 FastAPI 直接持有可信 owner 的调用，并按显式配置的 OpenAI/DeepSeek 费率快照计算；隔离 Agent 内部调用在建立签名 owner 传递前保持不归因。默认配置仍不会采集。

切片 4 增加了仅本机操作者可运行的只读聚合命令。它展示统计窗口、事件数、确认参与数、激活教师数、所有指标的分子/分母、可信等级错误率，以及按周聚合的 Week-1/Week-4 cohort 进度；同时明确标注样本是否达到 20–30 位目标。该命令没有 HTTP、浏览器或 Agent 入口，不输出逐人/逐任务信息，不读取正文，也不会在指标库缺失时创建空库。当前默认配置仍关闭采集且没有真实指标库，因此只读预演会安全返回“未就绪”，不能据此宣称已有 Beta 样本。

切片 5 增加一次性操作预演：七条安全检查只在自动删除的合成临时库中执行，覆盖告知、本人导出、运营读数、保留清理与退出删除；当前部署只做不含路径/密钥的只读 preflight。实际预演七项均通过，Beta 访问已开启，但本地部署仍明确报告 `COLLECTION_DISABLED`、`IDENTITY_SECRET_MISSING` 和 `METRIC_STORE_MISSING`，因此当前不具备邀请真实教师参与指标验证的技术配置条件，也没有产生任何真实指标。

## M14 当前进度

第一条切片建立了 `AccountIdentity` 深模块 Interface，并明确拆分 `account_id`、`tenant_id` 与现有私人内容使用的 `owner_id`。正式会话只把服务端解析出的 owner 注入业务模块，浏览器、Agent、模型及请求参数不能选择身份。内存与 SQLite 两个 adapter 证明 Interface 可替换；密码使用 scrypt，会话 token 只存摘要且可到期/撤销。正式身份、封闭测试与纯本地开发三种模式互斥；错误配置同时开启前两者时 fail closed。`/ready` 只检查当前模式需要的身份存储，本地模式不创建无用会话库，冲突模式明确降级。能力定义已上移到全局工作台边界，旧版单用户接口在任一账号模式均停用。

2026-09-10 经项目所有者明确调整边界，新增独立 `AccountRegistration` 和正式登录/注册网页。注册只接受邮箱、显示名称、密码与确认；账号、个人 tenant、稳定 owner、角色和能力全部由服务端生成，成功后签发正式 HttpOnly 会话。自助注册是独立部署开关且默认关闭，只在正式身份开启、Beta 关闭时生效；Agent 无注册入口。当前没有迁移现有 Beta/本地 owner 数据，也未实现邮箱验证、找回密码或 MFA，因此该能力仍不能被描述为已可无约束公网发布。

第二条切片的第一段增加了独立 `AccountAdministration` 操作者边界。本机命令可显式确认创建、停用账号和重置密码；停用或重置会原子撤销该账号全部旧会话，交互式密码不会出现在参数或回执中。正式会话清理默认只读预览，确认后只删除已过期或已退出记录；有效会话、异常记录和教师内容均保留。维护工具先只读验证配置库与精确 schema，不接受任意路径，也没有 HTTP、浏览器或 Agent 入口。

第二条切片的第二段增加了独立 `AccountLoginProtection` 边界。正式登录在应用层同时限制账号摘要与连接来源摘要，默认 15 分钟内分别允许 5 次与 30 次失败；安全事件只保存 HMAC 摘要、结果和时间，默认保留 168 小时，不保存邮箱、IP、密码、token 或请求正文。成功登录清零该账号此前失败窗口并轮换当前浏览器旧会话；登录防护密钥不足、存储不可用或安全事实无法写入时失败关闭。MFA 当前没有假装实现，个人商业账号、未来组织特权角色、恢复码与 step-up 路线已固定在登录安全 ADR 中。

第二条切片的第三段增加了独立 `AccountLifecycleAudit` 边界。创建、停用、密码重置与失效会话清理必须先写入 `started` 审计意图；审计密钥、路径、schema 或存储不可用时失败关闭。审计只保存动作、状态、时间、是否改变、受影响会话数以及目标/操作者的 HMAC，不保存邮箱、原始操作者标签、密码、token 或内部身份 ID。只读汇总仅返回动作/状态计数且不创建空库。当前操作者标签不是已认证管理员身份，两个 SQLite 过渡库也不能跨库原子提交；中断事件保留为 `started` 等待人工核对，不自动重试或猜测结论。

第二条切片的第四段增加 `VersionedHmacKeyRing`。登录防护与生命周期审计各自保留独立当前/旧密钥集合，新摘要只用当前版本并携带 key ID 与非敏感指纹；升级前的无版本摘要和既有版本化摘要都不批量重写。登录评估在过渡期跨版本统计，保留期内的版本化事件若失去对应密钥则登录和就绪检查失败关闭。只读 `keyring-status` 仅验证配置并输出版本 ID 与数量，不创建数据库或返回密钥、摘要、路径和身份。当前最多保留三个旧密钥，集中式密钥管理与审计密钥长期销毁政策尚未完成。

第二条切片的第五段增加 `LoginNetworkOrigin` 与 `HttpDistributedAccountLoginProtection`。本地 direct 模式继续忽略转发头；生产只接受显式 CIDR 白名单代理覆盖后的单一规范 `X-Forwarded-For` IP。分布式服务 adapter 在本地完成版本化 HMAC，只发送摘要候选、非敏感 key tag、策略与有界结果，且禁用重定向和环境代理。生产环境若仍选择 direct 或 SQLite，或代理/远端协议不可验证，登录与 `/ready` 失败关闭。仓库没有捆绑外部分布式原子服务，真实边缘、TLS、原子计数与告警仍需部署。

PostgreSQL tenant adapter 的第一段新增 `PostgresAccountIdentity`，保持既有正式身份 Interface 不变，并把账号、personal tenant、membership、稳定 owner 与摘要会话放入固定版本 schema。应用启动不建表；本机 schema 工具只允许“只读预演 → 指纹一致 → 明确确认”部署，未知目标拒绝写入。生产若仍选 SQLite、DSN/驱动/连接不可用或版本与列形状不符，身份服务失败关闭；旧 SQLite 运维命令在 PostgreSQL backend 下也拒绝运行。本段没有连接真实 PostgreSQL，也没有迁移任何现有账号、会话或 owner 内容。

PostgreSQL tenant adapter 第二段先新增 `OwnerDataInventory`，以固定目录只读清点七类 SQLite 私人业务存储和四类关联文件目录。直接 owner、继承 owner 和旧无 owner 表分别处理；未知表或 SQL 对象、关键列漂移、旧无 owner 行、链接和未完成引用对账的非空文件目录都会失败关闭。报告只返回数量、状态、稳定问题码和不含原始 owner 的指纹；没有 HTTP、浏览器、Agent 或模型入口，也没有迁移、更新或删除数据。

随后新增 `OwnerFileReconciliation`，对私人资料、题图、PDF 导入和试卷资源四个文件域执行只读引用对账。平面目录按数据库保存名核对，试卷目录按 paper owner 与全部不可变版本 asset ID 核对；缺失、孤儿、跨 owner 冲突、悬空引用、路径穿越、链接和 schema 异常都失败关闭。报告只含数量、问题码与证据指纹，不读取文件正文，也不迁移或修改数据。

第三段新增独立 `OwnerMigrationPlanner`。它要求操作者提交前两份只读报告的精确指纹，并把源 owner、目标 owner/tenant、33 张非旧版表中的对象、完整源记录指纹、父对象依赖和四类文件引用绑定为仅摘要计划。计划 schema v2 进一步记录每个文件的内容 SHA-256 与字节长度，使同名内容替换也会改变确认指纹。扫描后会再次执行清点、文件对账和完整对象/文件计划扫描，证据、记录内容、文件字节漂移、悬空或跨 owner 父子关系、计划依赖不闭合、对象重复和文件数量不一致都会失败关闭。输出不含 owner、tenant、路径、主键、文件名或正文，且固定 `execution_allowed=false`；没有 HTTP、浏览器、Agent 或模型入口，也没有连接目标 PostgreSQL、写入、复制、删除或保存计划。

第四段新增独立 `OwnerMigrationExecutor`。它在打开目标事务前要求布尔确认、确认计划指纹与预期计划指纹一致，并重新生成实时计划；任何变化都拒绝执行。注入的事务 adapter 必须提供目标状态、应用、摘要对账与完成标记；同一计划已完成时只在对账一致后幂等返回，首次执行则必须在同一事务内应用、核对计划/对象/文件摘要与数量后才能标记完成，对账失败由 adapter 回滚。当前只完成合成事务验证，没有具体 PostgreSQL 内容写入或文件复制 adapter，也没有迁移真实数据。

第五段新增 `PostgresOwnerMigrationSchema`，把目标绑定 run、对象暂存记录和文件发布记录收口到固定、操作者专用的 PostgreSQL 迁移落地区域。迁移目标使用独立私密 DSN，不复用运行时身份连接；部署只允许“只读预演 → 相同计划指纹 → 明确确认”，并由事务 advisory lock 串行化。独立本机 CLI 在未确认 apply 时不读取私密配置；未知既有结构、版本或列形状漂移、连接失败和计划变化都失败关闭。构造和应用启动不连接目标或建表，同版结构幂等返回。当前测试只使用合成连接，没有连接真实 PostgreSQL、创建真实 schema 或迁移任何真实数据；该区域也不是运行时业务内容库。

第六段新增内部 `OwnerMigrationObjectMaterializer`。它在任何目标写入前重算计划和目标绑定，并按固定查询目录以只读连接重读计划对象；对象集合、依赖、完整行指纹、顺序或数量变化均失败关闭。只有源 owner 的行能进入载荷，载荷中的 owner/tenant 改绑到目标，BLOB 使用明确 Base64 包装；私密载荷不进入计划、回执、错误或对象表示。本段没有 HTTP/Agent/CLI、PostgreSQL 写入或真实数据迁移。

第七段新增 `OwnerMigrationSourceFiles` 与 `OwnerMigrationFileMaterializer`。固定数据库引用、owner 过滤、安全路径解析和流式内容摘要由同一只读源 Interface 管理，Planner 与物化器不再维护两套规则。物化前核对完整计划、目标绑定、文件域、对象集合、SHA-256 和长度；真正写入未来 staging sink 时再次拒绝链接并在 EOF 复验内容。计划后或物化后换文件、短写和 I/O 异常都失败关闭，路径、引用名、owner 和正文不进入报告、错误或对象表示。当前没有具体 PostgreSQL 目标事务 adapter，没有复制/发布真实文件，也没有迁移真实数据；下一段把两类物化结果接入具体目标事务 adapter。

正式身份与网页注册功能在仓库默认关闭；本地 SQLite 仍是过渡 adapter。邮箱验证、账号找回、MFA 实现、已认证操作者/RBAC、不可抵赖审计、集中式密钥管理、外部可信边缘/原子限流部署、正式 PostgreSQL 业务内容 schema、具体目标事务 adapter、已提交迁移补偿恢复、真实 PostgreSQL 集成与 IDOR/tenant isolation Gate、对象存储、持久任务、Entitlement、订单、支付与退款仍未实现；详见 [`M14-COMMERCIAL-FOUNDATION.md`](M14-COMMERCIAL-FOUNDATION.md)。
