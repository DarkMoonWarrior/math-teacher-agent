# ADR：私有对象命名空间与保留策略边界

- 状态：已接受（M14 工程切片）
- 日期：2026-09-12
- 范围：私人原文件、不可变版本资源、导出文件与后台任务结果的对象键

## 背景

当前产品的私人正文已经由业务表中的 `owner_id` 隔离，但文件仍分散在多个本地目录，后台任务也只存在于单进程内存。若路由或不同存储 Adapter 各自拼接路径，原始 account、tenant、owner 或业务 ID 很容易进入对象键；仅知道另一个用户的路径也可能绕过数据库 owner 条件。云对象存储、持久任务和真实迁移不能建立在这类隐式约定上。

这一切片先固定对象命名和授权 Interface，不假装已经接入云存储或持久队列。

## 决策

新增 `PrivateObjectNamespace` 深模块。调用方只能提交服务端认证后得到的 `PrivateObjectScope(tenant_id, owner_id)`、固定 `PrivateObjectDomain` 和服务端持有的逻辑对象 ID；模块返回不可逆的 `PrivateObjectBinding`。

对象键满足以下规则：

1. account、tenant、owner、逻辑对象 ID、文件名和正文都不以明文进入对象键。
2. HMAC 输入同时绑定 schema、tenant、owner、对象域和逻辑 ID；任一维度变化都会得到不同键。
3. 新对象只使用当前版本密钥；读取时可在有界旧密钥集合内校验，支持轮换期间读取既有对象，不批量反查或改写身份。
4. 授权通过重新计算绑定完成。错误 owner、tenant、对象域、逻辑 ID、版本、保留策略或篡改键统一返回 `PRIVATE_OBJECT_ACCESS_DENIED`，不泄露哪一维不匹配。
5. 保留策略由对象域固定，浏览器、Agent 和模型不能选择：长期私人原稿与不可变版本随 owner 生命周期保留；临时导出在响应结束后删除；后台任务终态结果保留 24 小时。
6. 同一作用域、对象域和逻辑 ID 的对象键确定性相同，给后续幂等写入、重试和恢复提供稳定主键。

对象域当前覆盖私人资料原稿、题图 revision、PDF 原文件与裁剪、试卷/教案版本资源、临时导出和后台任务结果。新增对象类型必须先进入枚举和保留策略目录，不能由路由传入任意路径前缀。

## 安全与隐私

- `PrivateObjectScope` 的对象表示始终隐藏身份值，`PrivateObjectBinding` 的对象表示也隐藏内部 storage key。
- 对象键虽不含原始身份，仍是内部存储定位符，不能直接作为浏览器授权凭据；任何取写操作仍须经过当前正式会话和 `authorize()`。
- 密钥至少 32 字符，并复用版本化 HMAC 密钥环的 key ID、指纹、旧密钥数量和密钥材料不出现在表示中的约束。
- 当前测试使用合成 tenant/owner 和内存计算，不读取、复制、迁移或删除真实文件。

## Interface 与 Adapter 边界

`PrivateObjectNamespace` 负责身份绑定、对象域目录、保留策略、键格式、轮换兼容和失败关闭。未来本地文件、S3 兼容对象存储或队列结果存储只负责字节与持久化，不得重新解释 owner 权利或自行拼接键。

只有出现真实的部署差异时才增加存储 Adapter；当前切片不创建一个没有生产实现的通用云存储抽象。

## 未完成

- 现有原文件、不可变版本、导出和后台任务尚未迁到这一命名空间。
- 没有云对象存储 Adapter、持久队列、跨进程锁、上传分片、病毒扫描、对象版本锁、生命周期规则核对或灾备恢复。
- 没有真实 PostgreSQL + 对象存储的双向一致性 Gate。
- 密钥仍由部署配置提供，集中式密钥管理、轮换审计和长期销毁策略尚未完成。

因此本 ADR 只证明对象边界已经明确，不代表对象存储或持久任务已生产就绪。
