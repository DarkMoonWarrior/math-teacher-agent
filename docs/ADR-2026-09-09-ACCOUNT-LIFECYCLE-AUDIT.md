# ADR：操作者账号生命周期审计边界

日期：2026-09-09  
状态：M14 过渡实现；写操作审计已接入，已认证后台操作者与不可抵赖审计尚未实现。

## 背景

本机操作者可以创建、停用账号、重置密码和清理失效会话。这些能力没有 HTTP、浏览器或 Agent 入口，但仍属于高风险账号写操作。只返回一次性命令结果无法支持事故排查；直接记录邮箱、密码、token 或内部账号标识又会扩大敏感数据面。

## 决策

1. `AccountLifecycleAudit` 是独立深模块 Interface，不能并入登录限流事实、业务 analytics 或教师内容库。
2. 所有操作者写操作必须先成功持久化 `started` 事件，再触发账号或会话变更。审计密钥缺失、路径不安全、schema 不符或存储不可用时，操作失败关闭。
3. 审计库只保存动作枚举、`started`/`succeeded`/`failed`、服务端时间、是否改变和受影响会话数。目标账号线索和操作者标签分别用独立审计密钥做 HMAC；不得保存邮箱、原始操作者标签、密码、token、account/tenant/owner ID、文件路径、请求正文或教师内容。
4. CLI 的 `--operator` 只是本机操作者提供的审计线索，不是认证、授权或不可抵赖身份。它不会出现在回执或聚合读数中。未来后台必须把它替换为服务端认证的特权操作者主体。
5. `audit-summary` 只读取既有审计库并返回动作/状态计数，不返回 event ID、摘要或逐条事件；缺库时不创建空库。当前没有 HTTP、浏览器、Agent、导出或删除入口。
6. 身份库与审计库当前是两个 SQLite 过渡 adapter，不能跨库原子提交。先写 `started` 可保证审计不可用时不会变更；若进程在业务成功后、审计完成前中断，事件保留为 `started`，必须人工核对，不能自动解释为失败或重试写操作。

## 保留与访问

当前不自动删除生命周期审计，也不提供清理命令。正式保留期、法务依据、特权访问、导出、告警和销毁流程必须在生产存储及组织角色明确后单独批准；不能套用登录安全事实的 168 小时保留，也不能套用教师内容删除规则。

## 明确未解决

- 尚无已认证操作者、RBAC、双人审批、不可抵赖签名、集中式不可变日志或 SIEM 投递。
- `started` 异常事件只有聚合计数，尚无受控逐条调查工具和对账流程。
- 审计摘要已经带密钥版本，轮换顺序见 [`ADR-2026-09-09-HMAC-KEY-ROTATION.md`](ADR-2026-09-09-HMAC-KEY-ROTATION.md)；但旧密钥的长期保留/销毁和逐条受控关联仍须等待审计保留与调查政策。
- SQLite 只证明 Interface 和失败关闭语义，不是生产审计存储声明。
