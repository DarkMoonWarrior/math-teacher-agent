# ADR：M14 owner 迁移执行控制器

日期：2026-09-11

状态：M14 PostgreSQL tenant adapter 第二段的第四切片；执行控制器已实现，后续落地区域、数据库对象/文件流物化及合成验证的具体 PostgreSQL 目标事务 adapter 已建立。

## 决策

在任何具体迁移 adapter 之前，新增独立 `OwnerMigrationExecutor`。它不接 HTTP、浏览器、Agent 或模型，只接受操作者明确确认的计划指纹，并在打开目标事务前重新生成完整只读计划。确认值、预期计划和实时计划三者不完全相同时，不得访问目标存储。

目标实现必须通过很小的事务 Interface 提供四项能力：检查目标状态、应用计划、返回目标摘要对账、标记完成。控制器只允许 `empty` 进入首次执行；同一绑定下已经 `complete` 且对账一致时返回 `already_applied`，不会重复写入；`in_progress`、未知状态、其他计划或其他绑定全部失败关闭。

首次执行必须在同一 adapter 事务内完成“应用 → 对账 → 标记完成”。对象数、文件数、计划指纹以及对象/文件摘要集合任一不一致都会抛错，使事务 adapter 回滚。公开回执只有结果、计划/绑定摘要和数量，不包含 owner、tenant、主键、文件名、路径或正文。

## 当前验证

合成事务 adapter 验证了：

- 缺少精确确认时不会重新读计划，也不会打开目标事务；
- 实时计划变化时不会访问目标；
- 成功写入只有在摘要对账通过后才能标记完成；
- 同一计划重复执行不会重复应用；
- 对账失败会离开事务并回滚到执行前状态；
- 遗留 `in_progress`、错误绑定和错误计划都失败关闭；
- Planner 或 adapter 的原始异常不会进入稳定操作者错误。

## 明确未完成

- 尚无正式 owner-aware 运行时内容 schema 或生产文件 staging Adapter；具体 SQL 目标 adapter 目前只通过合成连接与文件事务验证；
- 尚未迁移、移动、更新或删除任何真实用户数据；
- 已提交文件发布缺失已有合成前向补偿；仍没有生产 Adapter、删除式回滚或灾难恢复；
- 尚未通过真实 PostgreSQL、IDOR、tenant isolation、故障注入或恢复 Gate。

后续切片已经实现固定迁移落地区域的预演/确认、计划内数据库对象和文件流的只读物化、具体 PostgreSQL 目标事务 adapter 的合成故障注入，以及已提交文件发布缺失的前向补偿。下一步验证 IDOR 与 tenant isolation；不得把合成前向补偿描述为生产恢复或真实迁移已经完成。
