# ADR：M14 owner 文件引用只读对账

日期：2026-09-10  
状态：M14 PostgreSQL tenant adapter 第二段的第二切片；文件引用对账已实现，迁移尚未开始。

## 背景

私人资料、题图识别、PDF 导入和历史试卷均把数据库事实与磁盘文件分开保存。只按目录复制会把其他 owner、孤儿文件或未受数据库约束的内容带入目标；只按数据库复制又可能遗漏文件、路径穿越或悬空父引用。上一切片因此将所有非空目录标为待对账。

## 决策

1. 新增独立 `OwnerFileReconciliation` 深模块，只供本机操作者运行，不接 HTTP、浏览器、Agent 或模型。
2. 四个文件域使用固定布局：私人资料以 `library_items.stored_name` 直接归属 owner；题图 revision 通过 asset 继承 owner；PDF 原文件和媒体裁剪通过 batch/file 链继承 owner；试卷资源以 paper 目录和所有不可变版本中的 asset ID 共同确定。
3. SQLite 只读打开且不初始化。未知表、视图、触发器、所需列漂移、悬空父引用、无法解析的试卷快照、路径穿越、链接、目录布局异常、同一文件跨 owner 引用、缺失文件或孤儿文件均失败关闭。
4. 对账同时读取所有 owner 的引用，只用于识别冲突和孤儿；报告只返回请求 owner 的引用/存在数量、全局异常数量、稳定问题码和摘要指纹，不返回 owner、路径、文件名、对象 ID、原始 JSON 或内容。
5. 每个 store 的证据指纹包含规范化引用集合与目录集合的摘要，使“数量相同但对象不同”不会得到相同证据；指纹不是迁移授权，后续迁移事务仍必须重新核对。
6. 缺少数据库和目录表示没有文件对象，不创建任何内容。文件根存在但数据库缺失且包含文件时一律阻塞。

## 操作者入口

```powershell
python -m app.modules.tenant_migration.file_reconciliation_cli --source-owner-id owner_teacher
```

退出码 `0` 表示当前四个文件域没有阻塞项，`2` 表示对账完成但发现阻塞，`1` 表示配置或对账不可用。命令不会读取文件正文，也不会写入、移动或删除文件。

## 尚未完成

- 没有把清点与文件对账结果转换为逐对象迁移计划，也没有生成目标 owner 映射。
- 没有写入 PostgreSQL、对象存储或迁移账本，没有复制或删除任何文件。
- 没有实现幂等执行、事务恢复、逐对象校验、切换、回滚或 IDOR/tenant isolation Gate。
- 没有运行真实数据对账；自动测试仅使用临时合成数据库和文件。
