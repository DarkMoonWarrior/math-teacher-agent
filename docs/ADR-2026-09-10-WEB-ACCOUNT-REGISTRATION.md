# ADR：网页个人账号注册边界

日期：2026-09-10
状态：M14 当前决策；已实现默认关闭的个人账号网页注册，生产发布前置能力仍未完成。

## 背景

M14 最初只允许本机操作者创建账号，公开 HTTP 只有登录、状态与退出。项目所有者随后明确要求正式登录与账号注册应由网页自身完成，而不是依赖开发人员启动或命令行代建账号。本决策只变更个人账号进入方式，不扩大到组织、学生、管理员或 Agent 代注册。

## 决策

1. 新增独立 `AccountRegistration.register_personal_account` Interface。登录、注册和操作者生命周期仍是三个不同职责，不能把浏览器注册输入复用为操作者命令。
2. 网页注册只接受邮箱、显示名称、密码和密码确认。`account_id`、个人 `tenant_id`、稳定 `owner_id`、`personal_owner` 角色和能力清单均由服务端生成；多余字段直接拒绝。
3. 注册成功自动签发与正式登录相同的不透明 HttpOnly、SameSite Strict 会话；公开响应不返回 account、tenant 或 owner 内部标识。
4. 自助注册使用独立 `production_self_registration_enabled` 部署开关，默认关闭；只有正式身份开启且 Closed Beta 关闭时可用。状态接口只公开是否允许显示注册入口。
5. 注册沿用正式身份的网络来源解析和双范围登录防护；保护存储或来源解析不可用时失败关闭。重复账号只返回稳定、非识别性的注册冲突，不回显邮箱或内部身份。
6. Agent、模型和内部 Tool 没有注册入口。现有本机操作者创建流程继续保留，用于恢复与受控运维，不是网页依赖。
7. 从 Beta 或固定本地 owner 切换到正式账号前必须另做逐对象身份映射、预览、对账和回滚；不得因启用登录页而静默产生空账号或让既有私人内容失去可见性。

## 尚未成立的生产条件

- 尚未实现邮箱所有权验证、账号激活邮件、找回密码、MFA、设备管理和最近重新认证。
- SQLite 仍是过渡 adapter；尚未完成 PostgreSQL、多进程一致性、外部边缘/原子限流部署、生产告警和已认证操作者/RBAC。
- 因此该网页流程是 M14 的工程能力，不等于允许无约束公网开放，也不能称为生产认证或商业发布完成。

本 ADR 仅在网页个人账号注册这一点上替代此前“无公开注册”的边界；其他 M14 安全、身份隔离和阶段门禁保持不变。
