## 1. 产品定位与唯一目标用户

产品是面向中国高中数学教师的可信 AI Agent 工作台。教师通过自然语言、题目图片、PDF 或私人教学资料描述需求，系统逐步协助完成搜题、解题、私人资料整理、组卷与教案等备课工作流，并为关键结果展示来源、权利、验证和教师复核状态。

它不是传统搜题站，也不是通用聊天机器人。长期竞争力来自高质量结构化题库、`MathVerifier`、`RightsGate`、`PrivateLibrary`、教材知识图谱、题目相似/变式关系、可控教师偏好，以及 Teacher Agent 对完整备课工作流的理解；不得为短期开发速度破坏或复制这些资产。

当前只服务中国高中数学教师。不开发学生端、家长端、小学、初中、其他学科、在线课堂、社区、学校 ERP、成绩管理或全功能 LMS。

## 2. 从历史规划继承的不可违反原则

1. 数学正确性优先；大模型输出不等于 `MathVerifier` 验证。
2. 题目和解析必须保留来源、权利、revision、审核与验证证据。
3. 来源或权利不明内容进入 quarantine/review，不进入商业公共题库。
4. 教师上传及其所有派生内容 private-by-default；private → shared/public 必须明确授权。
5. Agent 不直接访问 SQL、SQLite、PostgreSQL、ORM、数据库文件或教师私人文件。
6. 唯一业务链路是 Agent → allowlisted Tool → FastAPI 业务模块 → Rights/Permission/Validation → storage。
7. AI 产物默认 draft；Agent 不得 publish、批准权利、批准数学验证或永久删除。
8. 业务系统只依赖产品自有 `TeacherAgentRuntime`；DeepSeek Harness 和模型供应商必须可替换。
9. 不修改 Harness core；优先 adapter/plugin/tool/preset；不复制第二套搜索、核验、组卷和教案业务逻辑。
10. 每个阶段通过功能、可信、权利/隐私和工程 Gate 后才能进入下一阶段。
11. 现阶段优先模块化单体和清晰接口，不为“架构高级”提前拆微服务。
12. 辅助命制题永久属于创建教师的 `PersonalQuestionLibrary`，不存在进入 public/shared/team/school/commercial-approved 的产品路径。
13. 公共 Search、公共 QuestionBank、后台内容管理和其他 owner 均无权读取或管理辅助命制题；教师拥有命名、分类、编辑、导出、删除和永久删除自己私题的权利。
14. 面向教师展示的数学内容必须渲染为可读公式；不能把 LaTeX 源码作为默认正文，也不能把排版成功冒充数学验证通过。统一规范见 [`MATH-CONTENT-PRESENTATION.md`](MATH-CONTENT-PRESENTATION.md)。
15. 所有面向用户正式交付的 Agent 内容必须闭环完成。“草稿”只表示尚未由用户保存或确认，不表示允许残缺、已知错误或需要用户代替系统完成核心工作。辅助命题正式交付前必须具备完整题面、完整选项（如适用）、可读解析、由解析推导的标准答案和一致性审核；发现题面或解析问题必须在内部判责并返工，不能把半成品冒充完整草稿交给教师自行修错。教师可以自主编辑已完成内容，但不承担替 Agent 补全交付物的责任。
16. 题面通过独立审核后，系统可以在解析仍生成时把“不含答案与解析”的题面作为明确标注的实时中间快照展示；题面若进入完善流程，当前快照必须同步标记为调整中，只有再次审核通过的新 revision 才能恢复为已通过状态。正常完成交付仍必须具备完整题面、选项、解析和由解析推导的标准答案。
17. 辅助命题的单个候选或同一题解析重试耗尽不是用户终点。系统必须在后台继续完善题面、重生成解析或整题重命，直至交付完整正确题目；只有明确检测到大学范围内容时可以终止并说明边界。后台任务不与页面生命周期绑定，切换页面不得取消已受理任务。owner 可以随时显式停止任务；若停止时存在最新“已审核通过”题面，系统必须提供“保留题面/放弃题面”选择：保留结果可以进入当前 owner 的私题库，但必须将标准答案和解析都明确存为“无”、标注“缺少解析”，且不得冒充完整闭环或数学验证通过；尚未通过或正在调整的题面不得被保留。若用户选择放弃，则不保存该中间结果。
18. “上一次”和“命题历史”只能读取当前 owner 的结果，并区分完整题目与“仅题面、缺少解析”状态。owner 可以删除历史；未保存结果随历史删除，已保存私题仅隐藏历史入口，不得连带删除私题。明确标注缺少解析的私题允许教师在组卷时主动选择，组卷和导出中的解析/答案位置统一显示“无”，不得因此伪造解析；公共题库、公共搜索和其他 owner 永远不可见。
19. Paper Agent 中教师的明确选题与保存意图优先。知识范围和难度是选题完成后由系统自动归纳并写入双向细目表的分析维度，不是阻止保存或导出的门禁。题量、题型/分区、配分或总分未达到初始蓝图时必须明确提示“试卷尚未完善”，但教师经取消/确认二次选择后仍可保存当前精确版本。题目正确性、选项/答案/解析完整性、权利、owner、高中范围、重复与相似度门禁保持不变；尚未应用的页面编辑不得被静默忽略。

完整量化门禁见 [`PRODUCT-GATES.md`](PRODUCT-GATES.md)。

## 3. 已确认的新路线决策

项目所有者于 2026-08-22 确认在 M6 后插入两个独立里程碑：

1. **M7 多模态题目采集与图片解题**：解决截图/单题图片的文字与公式识别、原图保真、带图题视觉推理和可信 Solve 接入。
2. **M8 私有辅助命题 Agent**：教师描述命题要求，系统生成结构化草稿，并只保存到 owner 独占的私题库。

原 Paper、Lesson、Memory 及后续阶段依次顺延为 M9-M17。M0–M12 均已通过对应 Gate；项目所有者于 2026-09-05 明确确认进入 M13。M13 切片 1–5 已实现，但真实样本验证因样本不足延期；项目所有者于 2026-09-08 明确授权进入 M14，M13 Gate 仍未通过。

多模态解题不能退化为“OCR 文本后丢弃原图”。带几何图、函数图、坐标系、统计图或表格的题目必须保存受控原图/裁剪，并把视觉理解与 MathVerifier 证据分开。

辅助命题不是 Search 的兜底伪造。Search 空结果或教师不满意时可以显式转入辅助命题，但生成题必须视觉和数据上与真实检索结果分离。允许入口包括顶部命题导航、Search 空/不合适结果、“新任务”菜单与 Paper Agent 明确询问；任何入口都不得自动保存或自动加入试卷。

辅助命制题使用独立 `PersonalQuestionLibrary` 模块和 owner-isolated storage namespace，不以公共 `QuestionBank` 的一个可变 visibility 字段作为唯一隔离手段。该模块没有 publish/share 接口；后台运营/内容管理员没有内容查看和管理接口。详细规则见 [`M8-PRIVATE-QUESTION-AUTHORING.md`](M8-PRIVATE-QUESTION-AUTHORING.md)。

M14 第一切片建立生产身份深模块：`AccountIdentity` 验证账号并解析/撤销不透明会话；`AccountRegistration` 只建立个人账号并返回同一类正式会话；`account_id`、`tenant_id` 和现有私人内容的 `owner_id` 分别建模。项目所有者于 2026-09-10 明确把正式登录页和网页注册纳入本阶段。网页注册是独立、默认关闭的部署能力，只允许浏览器提交邮箱、显示名称、密码和密码确认；owner、tenant、角色与能力全部由服务器生成，Agent 仍无创建账号入口。业务模块只接收服务端解析出的 owner，浏览器、Agent、模型、请求正文和查询参数均无权选择身份。当前仅支持个人 `personal_owner`；没有组织角色或学生。正式身份、M12 Beta 访问和固定本地身份是互斥模式，同时开启正式身份和 Beta 时 fail closed。关闭的身份 adapter 不得创建存储；任何非本地账号模式必须停用缺少安全 owner 契约的旧版单用户接口。

SQLite 与内存实现只证明 Interface 可替换，不代表生产存储。密码和 session token 不得明文保存，登录错误不得泄露账号是否存在，公开响应不得返回 account/tenant/owner 内部标识。正式身份与自助注册都默认关闭，尚未创建真实账号或迁移真实数据；当前网页注册也不等于已完成邮箱验证、找回密码、MFA 或生产反滥用部署。后续必须按账号生命周期加固 → PostgreSQL tenant adapter 与逐对象对账/回滚 → 对象存储/持久任务 → Entitlement → 订单/支付/退款顺序推进；支付不能提前进入。完整边界见 [`M14-COMMERCIAL-FOUNDATION.md`](M14-COMMERCIAL-FOUNDATION.md)。

后续顺序以 [`ROADMAP.md`](ROADMAP.md) 为准：Solve → Private Library → 多模态图片解题 → 私有辅助命题 → Paper → Lesson → Memory → Beta 准备 → Beta 验证（真实验证延期） → 商业基础（当前） → Teacher Pro → 教研组 → 学校。

## 7. 内容、权利、私人资料、私题与发布

- 商业内容必须追踪 source、原始文件/页码、权利状态、商用/修改/公开权限、revision、教师审核和数学验证。
- 测试只使用 `data/test-fixtures` 的项目自建 synthetic 内容。
- `data/commercial-approved` 只接收通过完整发布门禁的内容；当前保持为空。
- OCR、拆题、知识点映射、教师校对和数学验证不会改变 private 所有权。
- 所有展示或导出必须区分 verified source、program verified、model reviewed 和 teacher review required。
- 辅助命制题固定为 `ai_generated + private_owner_only`；即使教师完成数学复核，也只改变验证状态，不改变可见性或发布资格。
- 教师可以对自己的辅助命制题命名、分类、编辑、复制、导出、移入回收站、恢复或永久删除；这些动作只影响当前 owner 的私题。
- Agent 不得永久删除；永久删除只能由当前 owner 在受认证 UI 中明确确认并经 FastAPI 业务模块执行。后台管理员无替用户查看、修改、恢复、发布或删除私题的内容管理入口。
- 商业化身份和存储必须以 tenant/owner isolation、IDOR 与跨 owner 自动测试证明隔离；不能以 UI 隐藏或约定替代权限。
